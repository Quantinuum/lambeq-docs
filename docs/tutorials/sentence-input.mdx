title: "Step 1. Sentence input"
---

The first part of the process in `lambeq` given a sentence, is to
convert it into a [string diagram](/lambeq/glossary/#term-string-diagram), according to a given
[compositional scheme](/lambeq/glossary/#term-compositional-model). `lambeq` can
accommodate any [compositional model](/lambeq/glossary/#term-compositional-model) that can encode sentences as
[string diagrams](/lambeq/glossary/#term-string-diagram), its native data structure. The
toolkit currently includes a number of
[compositional models](/lambeq/glossary/#term-compositional-model), using various
degrees of syntactic information: [bag-of-words](/lambeq/glossary/#term-bag-of-words) models do not use
any syntactic information,
[word-sequence models](/lambeq/glossary/#term-word-sequence-model) respect the order of
words, while fully syntax-based models are based on grammatical
derivations provided by a parser.

## Pre-processing and tokenisation

Depending on the form of your data, some preprocessing steps may be
required to make it appropriate for `lambeq` use. Section
[sec-preprocessing](/lambeq/nlp-101/nlp-data/#text-pre-processing) in the [NLP-101 tutorial](/lambeq/nlp-101/nlp-intro/)
provides more information about this. Here we will mainly talk about
[tokenisation](/lambeq/nlp-101/nlp-data/#tokenization), which is crucial in getting
correct derivations from the [Bobcat](/lambeq/glossary/#term-bobcat) parser.

The term *tokenisation* refers to the process of breaking down a text or
sentence into smaller units called *tokens*. In `lambeq` these tokens
correspond to words, since the parser needs to know exactly what kind of
words or symbols and punctuation marks are included in the sentence in
order to provide an accurate grammatical analysis.

By default, Bobcat parser assumes that every sentence is delimited by a
whitespace, as below:

``` python
"John gave Mary a flower"
```

Note however that when working with raw text, this is rarely the case.
Consider for example the sentence:

``` python
"This sentence isn't worth £100 (or is it?)."
```

A naïve tokenisation based on white spaces would result in the following
list of tokens:

``` python
["This", "sentence", "isn't", "worth", "£100", "(or", "is", "it?)."]
```

missing, for example, that “isn’t” represents actually two words and
“(or” is not a proper word.

In `lambeq`, tokenisation is provided through the
[`Tokeniser`](/lambeq/api/lambeq.tokeniser#lambeq.tokeniser) class hierarcy, and specifically by using the
[`SpacyTokeniser`](/lambeq/api/lambeq.tokeniser#lambeq.tokeniser.SpacyTokeniser) class, based on the popular NLP package
[spaCy](https://spacy.io). Here is an example:

``` python
from lambeq import SpacyTokeniser

tokeniser = SpacyTokeniser()
sentence = "This sentence isn't worth £100 (or is it?)."
tokens = tokeniser.tokenise_sentence(sentence)
tokens
```

```text
['This',
 'sentence',
 'is',
 "n't",
 'worth',
 '£',
 '100',
 '(',
 'or',
 'is',
 'it',
 '?',
 ')',
 '.']
```

We can then pass the list of the tokens to the parser, setting the
`tokenised` argument of the `sentence2diagram`
method to True.

``` python
from lambeq import BobcatParser

parser = BobcatParser(verbose='suppress')
diagram = parser.sentence2diagram(tokens, tokenised=True)

diagram.draw(figsize=(23,4), fontsize=12)
```

![](/lambeq-assets/tutorials/sentence-input/sentence-input_files/figure-commonmark/cell-3-output-1.png)

<Callout type="info">

More details about [DisCoCat](/lambeq/glossary/#term-discocat) and syntax-based models will follow below.

</Callout>

To tokenise many sentences at once, use the
[`tokenise_sentences`](/lambeq/api/lambeq.tokeniser#lambeq.tokeniser.SpacyTokeniser.tokenise_sentences) method:

``` python
sentences = ["This is a sentence.", "This is (another) sentence!"]

tok_sentences = tokeniser.tokenise_sentences(sentences)
tok_sentences
```

```text
[['This', 'is', 'a', 'sentence', '.'],
 ['This', 'is', '(', 'another', ')', 'sentence', '!']]
```

Finally, `lambeq` provides tokenisation at the sentence-level:

``` python
text = "I love pizza. It is my favorite food. I could eat it every day!"
sentences = tokeniser.split_sentences(text)
sentences
```

```text
['I love pizza.', 'It is my favorite food.', 'I could eat it every day!']
```

<Callout type="info">

To simplify the rest of this tutorial, all sentences in the following sections will be delimited by white spaces, so that the parser can tokenise them properly without extra handling.

</Callout>

## Syntax-based model: DisCoCat

In order to obtain a [DisCoCat](/lambeq/glossary/#term-discocat)-like output, we first use the
[`BobcatParser`](/lambeq/api/lambeq.text2diagram#lambeq.text2diagram.BobcatParser) class from [`text2diagram`](/lambeq/api/lambeq.text2diagram#lambeq.text2diagram)
package, which, in turn, calls the [parser](/lambeq/glossary/#term-parser), obtains a
[CCG](/lambeq/glossary/#term-combinatory-categorial-grammar-ccg) derivation for the
sentence, and converts it into a [string diagram](/lambeq/glossary/#term-string-diagram). The code below
uses the default [Bobcat](/lambeq/glossary/#term-bobcat) parser in order to produce a
[string diagram](/lambeq/glossary/#term-string-diagram) for the sentence “John walks in the park”.

<Callout type="info">

`lambeq`'s string diagrams are objects of the class [`Diagram`](/lambeq/api/lambeq.backend/grammar#lambeq.backend.grammar.Diagram).

</Callout>

``` python
from lambeq import BobcatParser

sentence = 'John walks in the park'

# Parse the sentence and convert it into a string diagram
parser = BobcatParser(verbose='suppress')
diagram = parser.sentence2diagram(sentence)

diagram.draw(figsize=(14,3), fontsize=12)
```

![](/lambeq-assets/tutorials/sentence-input/sentence-input_files/figure-commonmark/cell-6-output-1.png)

<Callout type="info">

Recall from previous section that when the input to [`sentence2diagram`](/lambeq/api/lambeq.text2diagram#lambeq.text2diagram.CCGParser.sentence2diagram) method is a list of tokens, you should also set `tokenised` argument to True (by default is set to False).

</Callout>

Another case of syntax-based models in `lambeq` is
[tree readers](/lambeq/tutorials/sentence-input/#tree-readers), which will be presented later in
this tutorial.

## Bag-of-words: Spiders reader

[DisCoCat](/lambeq/glossary/#term-discocat) is not the only [compositional model](/lambeq/glossary/#term-compositional-model) that
`lambeq` supports. In fact, any compositional scheme that manifests
sentences as
[string diagrams](/lambeq/glossary/#term-string-diagram)/[tensor networks](/lambeq/glossary/#term-tensor-network)
can be added to the toolkit via the readers of the
[`text2diagram`](/lambeq/api/lambeq.text2diagram#lambeq.text2diagram) package. For example, the
`spiders_reader` object of the
[`LinearReader`](/lambeq/api/lambeq.text2diagram#lambeq.text2diagram.LinearReader) class represents a sentence as a
“[bag-of-words](/lambeq/glossary/#term-bag-of-words)”, composing the words using a [spider](/lambeq/glossary/#term-spider) (a
commutative operation).

``` python
from lambeq import spiders_reader

# Create string diagrams based on spiders reader
spiders_diagram = spiders_reader.sentence2diagram(sentence)

# Not a pregroup diagram, we can't use grammar.draw()
spiders_diagram.draw(figsize=(13,6), fontsize=12)
```

![](/lambeq-assets/tutorials/sentence-input/sentence-input_files/figure-commonmark/cell-7-output-1.png)

## Word-sequence models: Cups and stairs readers

The [`LinearReader`](/lambeq/api/lambeq.text2diagram#lambeq.text2diagram.LinearReader) class can be used to create any kind of
model where words are composed in sequence, from left to right. For
example, the `cups_reader` instance of this
class generates a “[tensor train](/lambeq/glossary/#term-tensor-train)”.

``` python
from lambeq import cups_reader

# Create string diagrams based on cups reader
cups_diagram = cups_reader.sentence2diagram(sentence)

cups_diagram.draw(figsize=(12,2), fontsize=12)
```

![](/lambeq-assets/tutorials/sentence-input/sentence-input_files/figure-commonmark/cell-8-output-1.png)

Note the use of a `START` symbol in the beginning of the sentence,
represented as an order-1 tensor (a vector). This ensures that the final
result of the computation (that is, the representation of the sentence)
will be again a tensor of order 1.

Another pre-made word-sequence model is provided by the
`stairs_reader` instance. This model
combines consecutive words using a box (“cell”) in a recurrent fashion,
similarly to a recurrent neural network.

``` python
from lambeq import stairs_reader

stairs_diagram = stairs_reader.sentence2diagram(sentence)
stairs_diagram.draw(figsize=(12,5), fontsize=12)
```

![](/lambeq-assets/tutorials/sentence-input/sentence-input_files/figure-commonmark/cell-9-output-1.png)

## Tree readers

A [CCG](/lambeq/glossary/#term-combinatory-categorial-grammar-ccg) derivation follows
a biclosed form ([Yeung & Kartsaklis, 2021](/lambeq/bibliography/#bib-yeung_2021)), which can be directly interpreted
as a series of compositions without any explicit conversion into a
[pregroup](/lambeq/glossary/#term-pregroup-grammar) form. Class [`TreeReader`](/lambeq/api/lambeq.text2diagram#lambeq.text2diagram.TreeReader)
implements a number of compositional models by taking advantage of this
fact. In order to demonstrate the way they work, it would be useful to
first examine how a CCG diagram looks like:

<div style={{ "display": "flex", "justifyContent": "center" }}><img src="/lambeq-assets/_static/images/ccg-diagram.png" width="350" /></div>

Even without knowing the specifics of CCG syntax, it is not difficult to
see that the verb “gave” is first composed with the indirect object
“Mary”, then the result is composed with the noun phrase “a flower”
which correspond to the direct object, and finally the entire verb
phrase “gave Mary a flower” is further composed with the subject “John”
to return a sentence. A [`TreeReader`](/lambeq/api/lambeq.text2diagram#lambeq.text2diagram.TreeReader) follows this order of
composition, as demonstrated below.

``` python
from lambeq import TreeReader

reader = TreeReader()
sentence = "John gave Mary a flower"

tree_diagram = reader.sentence2diagram(sentence)
tree_diagram.draw(figsize=(12,5), fontsize=12)
```

![](/lambeq-assets/tutorials/sentence-input/sentence-input_files/figure-commonmark/cell-10-output-1.png)

Note that in this default call, composition is handled by a single
“cell” named `UNIBOX`. This can be changed by passing an explicit
argument of type [`TreeReaderMode`](/lambeq/api/lambeq.text2diagram#lambeq.text2diagram.TreeReaderMode) to the reader’s
constructor. There are three possible choices:

- `NO_TYPE` is the default, where all compositions are handled
  by the same `UNIBOX` cell (above diagram).
- `RULE_ONLY` creates a different cell for each CCG rule.
- `RULE_TYPE` creates a different cell for each (rule, type)
  pair.

For example:

``` python
from lambeq import TreeReader, TreeReaderMode

reader = TreeReader(mode=TreeReaderMode.RULE_ONLY)
sentence = "John gave Mary a flower"

tree_diagram = reader.sentence2diagram(sentence)
tree_diagram.draw(figsize=(12,5), fontsize=12)
```

![](/lambeq-assets/tutorials/sentence-input/sentence-input_files/figure-commonmark/cell-11-output-1.png)

In the above, each unique CCG rule gets its own box: FA boxes correspond
to forward application, and BA boxes to backward application. For
certain tasks, making the composition box rule-specific might lead to
better generalisation and overall performance.
